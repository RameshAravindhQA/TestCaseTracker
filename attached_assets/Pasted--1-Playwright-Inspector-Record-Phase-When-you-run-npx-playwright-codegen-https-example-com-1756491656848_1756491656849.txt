🔎 1. Playwright Inspector – Record Phase

When you run:

npx playwright codegen https://example.com


Playwright launches a browser instance with instrumentation hooks enabled. Here’s what happens technically:

Instrumentation Layer

Playwright attaches event listeners to the browser (Chromium, Firefox, WebKit).

It listens to DOM events (click, input, navigation, hover, etc.) at the protocol level (CDP for Chromium, WebSocket protocol for Firefox/WebKit).

It also tracks network requests, navigations, and frames.

Event Capturing

When you click a button, Playwright captures:

The element’s selector (text=Login, #username, input[name="email"])

The action (click, fill, hover, etc.)

When you type in an input, it records page.fill("selector", "value").

Selector Engine

Playwright dynamically generates the best possible locator using:

Accessibility attributes (aria-label, role)

CSS (#id, .class, input[name="email"])

Text content (text=Login)

It tries to avoid brittle selectors like xpath unless necessary.

Code Generation

Each user interaction is translated into Playwright API calls:

await page.goto('https://example.com');
await page.fill('input[name="username"]', 'testuser');
await page.click('text=Login');


The generated code is shown live in the Playwright Inspector UI.

▶️ 2. Playwright Inspector – Play/Replay Phase

When you run the generated script (node test.spec.js), this happens:

Test Runner / Script Execution

Node.js runs the script (usually via Playwright Test or plain Node).

Playwright connects to a browser via its automation protocol (CDP / WebKit / Firefox protocol).

API → Protocol Translation

A line like:

await page.click('text=Login');


is converted into:

Locate element (querySelector) using Playwright’s selector engine.

Ensure element is ready (visible, stable, not detached).

Dispatch a click event at the right coordinates via the browser protocol.

Auto-Waits & Assertions

Playwright automatically waits for:

DOM stability (no detachment)

Element to be visible/enabled

Navigation/async events after the action

That’s why you don’t usually need manual sleeps.

Execution Flow in Inspector

If you run with PWDEBUG=1, Inspector pauses at each step.

You can step through actions, check locators, retry selectors, and resume execution.
